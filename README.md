# Версии клиентского API — плагин Agents Hub

Плагин для хабов, к которым подключаются клиенты вне страницы: приложение на телефоне или Mac, свой скрипт.
Ядро и код хаба не меняет.

API хаба (`/api/stream`, `/api/timeline`, действия — раздел «Свой клиент» в `EXTENDING.md` хаба) меняется вместе с
хабом. Страница и Telegram обновляются с ним в один день, а приложение на телефоне — нет: его надо собрать, выпустить
и поставить. Плагин убирает эту связку:

- клиент написан под одну **версию клиентского API** — её вид записан в `contract/v1.json`;
- клиент называет версию хабу: берёт с него скрипт `/ext/<плагин>/v1.js` (и шлёт заголовок `X-Hub-Api: 1`);
- скрипт — набор правил, которые приводят нынешние снимок, ленту и запросы хаба к виду этой версии. Клиент
  выполняет его у себя и пропускает через правила всё, что получает и шлёт;
- хаб изменил API — дописывается правило в `v1.js`, владельцы обновляют плагин. Приложения остаются как были.

Плагина на хабе нет — клиент читает хаб как есть: работает, пока его версия совпадает с нынешним API.

## Поставить

```
hub market add <аккаунт>
hub market install <аккаунт>/hub-client-api
```

На странице плагин ничего не показывает. Новое — `hub market update client-api`; обновлять стоит вместе с хабом.

## Правила

`v1.js` кладёт в `HubClientAPI` версию `api`, выпуск `rev` и нужные из трёх функций над JSON:

| Правило | Что получает | Что отдаёт |
|---|---|---|
| `snapshot(s)` | снимок хаба (`/api/stream`: `snapshot` с наложенными `patch`) | снимок в виде версии |
| `timeline(t)` | ответ `/api/timeline` | ответ в виде версии |
| `request({method, path, query, body})` | запрос клиента в виде версии | запрос, какого ждёт нынешний хаб |

Правила нет — данные идут как есть, клиент на него времени не тратит. Правило упало — клиент берёт данные без него.
Правила копятся и должны работать с прежними выпусками хаба тоже: смотрите на сами данные (есть ли поле), а не на
номер версии хаба. Образец — `tests/future-v1.js`.

Выпуск правил 4: служебная шапка отчёта (`request_id`, `from`, `to`) убирается из видимого текста, статус остаётся
читаемым, результат идёт первым, evidence и follow-up — отдельными абзацами. Длинные однострочные ответы разбиваются
на абзацы без пересказа. Исходник остаётся в `source_text`, журнал не меняется. Слова владельца, готовая разметка,
код и незнакомые шапки сохраняются. Автор, номера сообщений, вложения и маршрутизация не меняются.
Приложения подхватывают правила при подключении и при очередной фоновой проверке; пересборка не нужна.

Новая версия (`v2.js`, `contract/v2.json`) нужна, когда клиенту дают то, чего в версии 1 выразить нельзя. `v1.js`
при этом остаётся: прежние приложения продолжают работать.

## При каждом выпуске хаба

```
node tools/check.mjs --hub http://127.0.0.1:8787 --core <папка кода хаба>
```

Сверка берёт у хаба снимок и ленты сессий, пропускает через правила и сравнивает с договором; по коду хаба — есть ли
пути запросов клиента. Расхождение названо по имени (`snapshot.sessions[].state: нет поля`) — на него пишется правило
в `v1.js`, `rev` и `version` в `hub-plugin.json` растут на единицу. Новые поля и новые виды строк ленты расхождением
не считаются: клиент их не замечает.

## Постоянная сверка

```
node tools/watch.mjs --hub http://127.0.0.1:8787 --journal <папка состояния хаба>/journal.jsonl
```

Берёт правила с самого хаба (те же, что у клиентов) и смотрит: эталонные ленты (`tests/reference/`) — словами
владельца показаны только его сообщения, ответы и файлы на месте; живые ленты всех сессий — правила не теряют строк,
а сообщения ядра, плагинов, расписания и поручения другим сессиям не выданы за слова владельца; по журналу — каждое
слово владельца за последние часы есть в ленте. Каждый вызов клиентов (запросы договора, поток страницы, модули разделов и их запросы данных) пробуется на живом хабе, а с `--core <папка>` сверяется с кодом. Норма — молчит; расхождение — список и код 1. Раз в час монитором хаба:

```
hub schedule add --id client-api-watch --every 1h --command "node <плагин>/tools/watch.mjs --hub http://127.0.0.1:8787 \
  --journal <журнал> --state <файл> --tell 'hub send hub-dev'"
```

`--tell` получает список аргументом — один раз на одно и то же расхождение.

## Клиенту

1. Найти в `extensions` снимка плагин с именем `client-api` (или `<аккаунт>:client-api`) и взять `/ext/<имя>/v1.js`.
2. Выполнить скрипт в песочнице без сети и файлов (JavaScriptCore, QuickJS, `node:vm`) — он только определяет
   `HubClientAPI`. `api` не тот — не использовать.
3. Снимок после каждого события потока — через `snapshot`, ответы ленты — через `timeline`, свои запросы — через
   `request`. Скрипт перечитывать при подключении к потоку.
